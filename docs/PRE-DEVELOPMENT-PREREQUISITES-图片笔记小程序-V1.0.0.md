## 1. 结论

目前项目还不能直接进入完整业务开发。

前端静态页面可以先行开发，但登录、上传、图片访问、标签事务、注销清理等功能至少被“云开发环境尚未准备”阻塞。真正需要提前取得的不是大量 API Key，而是：

1. 小程序账号和 AppID 的实际使用权限。
2. 已开通并绑定小程序的微信云开发环境。
3. 云开发环境 ID、地域、套餐和付费主体。
4. 数据库、云存储、云函数、图片处理和定时任务的资源配置。
5. 用户上传图片、备注和标签的内容安全及隐私合规方案。
6. TDesign、Node.js 和 `wx-server-sdk` 的版本基线。

当前最直接的阻塞点是：

- `miniprogram/app.js` 中的 `env` 为空。
- `miniprogram/envList.js` 中没有任何环境配置。
- 项目没有根目录或小程序目录下的 `package.json`、依赖锁文件及 `miniprogram_npm` 构建产物。
- 六个业务数据库集合、七个业务云函数和定时触发器均未创建。
- 现有代码仍基本是微信云开发 QuickStart 模板。

## 3. Key、凭据和环境标识清单

### 3.1 当前架构必须提供

#### 小程序 AppID

当前公共配置中已有：

```text
wx536ce93aa8c43024
```

AppID 是应用标识，不属于高敏感密钥，但必须确认实际归属和可用权限。

#### 云开发环境 ID

这是当前唯一明确缺失、且小程序运行时必须使用的环境标识。

建议不要只提供一个无语义字符串，而是建立环境映射：

```text
development -> cloud-xxx-dev
testing     -> cloud-xxx-test
production  -> cloud-xxx-prod
```

`envId` 本身不是传统意义上的密钥，但生产环境 ID 不应散落在业务代码中。应通过统一环境配置模块管理，并避免开发环境误调用生产资源。

### 3.2 当前架构不需要提供

| 凭据 | 是否需要 | 原因 |
|---|---:|---|
| 微信小程序 AppSecret | 否 | 当前通过 `wx.cloud.callFunction()` 和 `cloud.getWXContext().OPENID` 完成身份识别 |
| 腾讯云 SecretId/SecretKey | 否 | 使用微信开发者工具部署，以及云函数访问同环境数据库和存储时不需要 |
| COS AccessKey | 否 | 同一云开发环境中通过 `wx-server-sdk` 操作云存储，不需要客户端持有 COS 密钥 |
| TDesign 授权 Key | 否 | TDesign Miniprogram 是开源 npm 组件 |
| 独立服务器域名和 HTTPS 证书 | 否 | 当前为纯微信云开发架构，不依赖外部 HTTP 后端 |

严禁将以下内容写入小程序客户端、`project.private.config.json` 或 Git 仓库：

- AppSecret
- SecretId
- SecretKey
- 第三方审核服务 API Key
- 第三方监控或客服服务 Token
- 可直接管理生产云资源的长期凭据

### 3.3 仅在特定扩展场景下需要

| 场景 | 可能需要的凭据 | 推荐存放位置 |
|---|---|---|
| CI/CD 自动创建、配置或部署云资源 | CAM 子账号 SecretId/SecretKey 或 CLI 登录凭据 | CI Secret Store |
| 直接调用腾讯云 IMS 图片内容安全 API | CAM 子账号凭据或服务角色 | 云函数环境变量或凭据管理服务 |
| 调用第三方客服、监控、审核服务 | 对应 API Key | 云函数环境变量 |
| 建设外部后台管理系统 | 服务端鉴权凭据 | 服务端运行环境 |

如需使用 CAM 凭据，应创建最小权限子账号，不使用腾讯云主账号永久密钥。

## 4. 需要开通和配置的云服务

### 4.1 微信云开发环境

创建环境前必须决定：

- 环境归属的小程序账号。
- 关联的腾讯云账号及实名认证主体。
- 环境地域。
- 套餐版本及付费主体。
- 是否开启超限按量。
- 是否启用自动续费。
- 费用、容量和调用量告警的接收人。
- dev、test、prod 是否使用独立环境。

推荐环境规划：

| 环境 | 用途 | 数据要求 |
|---|---|---|
| dev | 日常开发和接口联调 | 可重置，不使用真实用户数据 |
| test | 验收、回归、并发和升级验证 | 使用脱敏测试数据，配置尽量与生产一致 |
| prod | 正式用户 | 严格权限、监控、备份和变更控制 |

开发环境和生产环境不应共用数据库、云存储目录或定时清理任务。

CloudBase 当前采用套餐资源与超限按量相结合的计费方式。环境资源耗尽、欠费或套餐到期会直接影响数据库、云存储、云函数和定时触发器，因此付费与告警配置不能留到正式上线当天。

参考资料：

- [CloudBase 新手指引](https://cloud.tencent.com/document/product/876/56375)
- [CloudBase 价格文档](https://cloud.tencent.com/document/product/876/75213)

### 4.2 云数据库

需要创建以下六个集合：

```text
users
photos
notes
tags
photo_tags
deletion_tasks
```

必须建立架构文档列出的全部索引。其中以下两个唯一索引属于业务正确性的基础设施，不能等到功能开发结束后再补：

```text
tags:
  (_openid, normalized_name) UNIQUE

photo_tags:
  (_openid, photo_id, tag_id) UNIQUE
```

数据库准备工作应包括：

1. 创建集合。
2. 配置集合安全权限。
3. 创建普通索引和唯一索引。
4. 编写可重复执行的初始化或验收脚本。
5. 验证唯一键冲突的实际错误结构。
6. 验证 Node SDK 事务冲突和重试行为。
7. 为已有开发测试图片回填 `tag_count: 0`。
8. 回填完成后再建立未分类查询索引。

数据库权限建议：

- 小程序客户端不直接写业务集合。
- `tags` 和 `photo_tags` 明确禁止客户端直接读写。
- 所有业务读写通过云函数执行。
- 云函数从 `cloud.getWXContext().OPENID` 获取身份。
- 所有查询将 `_openid` 作为第一数据隔离条件。
- `DELETING`、`DELETED` 用户的业务访问由服务端统一拒绝。

CloudBase 事务目前只能在服务端运行，且只有 Node SDK 支持；唯一索引可以作为并发写入的最终防线。

参考资料：

- [CloudBase 索引管理](https://docs.cloudbase.net/database/data-index)
- [CloudBase 事务操作](https://docs.cloudbase.net/database/transaction)

### 4.3 云存储与图片处理

需要提前开通或验证：

- 云存储桶地域与云开发环境一致。
- 文件访问权限默认为私有。
- 小程序能够通过 `wx.cloud.uploadFile()` 上传。
- 云函数能够删除本人文件。
- 云函数能够通过 `cloud.getTempFileURL()` 生成临时访问链接。
- 临时链接能够正常使用 `imageMogr2` 图片处理参数。
- 万象优图 CI 图片处理能力是否需要额外开通或计费。
- 云存储容量、下载流量和图片处理费用是否满足预估。
- 500MB/用户的业务配额与云环境总容量是否匹配。

图片处理参数应由云函数统一拼接，客户端不应自行组合私有文件 URL。

需要特别注意：临时 URL 可能已经包含查询参数。实现时不能固定使用 `?imageMogr2/...`，应根据 URL 是否已有查询参数选择 `?` 或 `&`。

参考资料：

- [CloudBase 云存储图片处理](https://docs.cloudbase.net/storage/ci-cos-processing)

### 4.4 业务云函数

需要创建并部署七个业务云函数：

```text
user
photo
note
upload
account
tag
cleanup
```

每个函数都应提前确定：

- Node.js 运行时版本。
- `wx-server-sdk` 版本。
- 内存规格。
- 超时时间。
- 最大并发。
- 环境变量。
- 日志级别及日志保留周期。
- 告警规则。
- 部署和回滚方式。

当前 QuickStart 云函数依赖：

```json
"wx-server-sdk": "~2.4.0"
```

该版本不应未经验证直接复制到新函数。应选择一个经过以下能力验证的统一版本：

- Node.js 18 兼容性。
- 数据库事务。
- 临时文件 URL。
- 云存储删除。
- 服务端日期和原子更新。
- 当前云开发环境支持情况。

### 4.5 cleanup 定时触发器

架构设计为每日 03:00 执行：

```json
{
  "triggers": [
    {
      "name": "dailyCleanup",
      "type": "timer",
      "config": "0 0 3 * * * *"
    }
  ]
}
```

开发前还需确认：

- Cron 表达式对应的时区。
- cleanup 单次运行超时。
- 单批处理数量。
- 失败游标的持久化位置。
- 环境套餐能否支撑每日扫描和计数校正。
- 任务失败、连续失败和积压的告警方式。
- 触发器部署是否纳入发布流程。

仅将 `config.json` 写入仓库并不代表触发器已经生效。部署后还需要在控制台确认触发器已上传并启用。

参考资料：

- [CloudBase 定时触发器](https://docs.cloudbase.net/cloud-function/timer-trigger)

当前 `uploadCloudFunction.sh` 只部署 `quickstartFunctions`，不能作为七个业务云函数的正式部署脚本。

## 5. 开发前必须补齐的技术决策

### 5.1 用户上传内容安全

这是当前技术架构最大的缺口。

项目允许用户上传图片，并输入备注和标签名称。开发前必须决定：

- 图片上传后是先审核再可见，还是先展示后异步处置。
- 标签名称和备注是否进行文本内容安全检测。
- 是否增加 `PENDING_REVIEW`、`PASS`、`REVIEW`、`REJECT`、`ERROR` 等状态。
- 审核拒绝后是否立即删除云存储对象。
- 审核服务超时或异常时允许上传还是阻断。
- 疑似违规内容是否需要人工复核。
- 用户是否具有申诉或客服入口。
- 审核结果和审计日志保留多久。
- 内容审核调用成本由谁承担。

可选方案：

1. 使用微信内容安全接口，通过云调用接入。
2. 开通 COS 图片增量审核。
3. 接入腾讯云图片内容安全 IMS。
4. 接入其他经过合规评估的第三方服务。

如使用 COS 图片增量审核，可对存储桶新增图片自动检测，并对违规内容执行冻结等策略，但这属于额外服务和计费决策。

参考资料：

- [COS 图片增量审核](https://cloud.tencent.com/document/product/436/45433)
- [腾讯云图片内容安全](https://cloud.tencent.com/document/product/1125)

如果产品明确只做用户本人私有存储，也应由产品和合规负责人确认是否可以不接内容审核，不应由开发人员默认省略。

### 5.2 TDesign 版本和组件兼容性

当前仓库没有：

- 根目录 `package.json`
- `miniprogram/package.json`
- npm lockfile
- `miniprogram_npm`
- `.gitignore`

TDesign 官方建议使用 npm 安装。当前可参考的正式版本为 `1.15.0`，可按架构建议锁定 Minor 版本：

```json
{
  "dependencies": {
    "tdesign-miniprogram": "~1.15.0"
  }
}
```

正式锁定前应制作一个组件兼容性 Spike，并至少验证：

- `t-navbar`
- `t-image`
- `t-image-viewer`
- `t-popup`
- `t-dialog`
- `t-message`
- `t-tag`
- `t-tab-bar`
- `t-result`
- `t-loading`
- `t-textarea`
- `t-checkbox`

架构文档列出了 `t-scroll-view`，但当前 TDesign Miniprogram 官方组件概览中没有该组件。应改用微信原生 `<scroll-view>`，或重新选择对应实现。

参考资料：

- [TDesign Miniprogram GitHub](https://github.com/Tencent/tdesign-miniprogram)
- [TDesign Miniprogram 组件概览](https://static.tdesign.tencent.com/miniprogram/)

### 5.3 TabBar 实现方案

技术架构同时出现了：

- `app.json` 原生 `tabBar`
- 页面组件中的 `t-tab-bar`

开发前必须统一为一种方案：

#### 方案 A：微信原生 TabBar

优点：

- 路由和系统行为稳定。
- 实现成本较低。
- `wx.switchTab()` 行为自然。

缺点：

- 自定义视觉能力有限。

#### 方案 B：自定义 TabBar/TDesign TabBar

优点：

- 更容易与设计系统保持一致。

缺点：

- 需要配置和维护自定义 TabBar。
- 页面状态、选中态、路由同步和安全区适配更复杂。

未经决策不应同时渲染原生和 TDesign 两套底部导航。

### 5.4 临时缩略图不能长期存入 notes

架构将 `notes.photo_thumbnail_url` 设计为数据库冗余字段，同时又要求图片 URL 通过 `cloud.getTempFileURL()` 生成。

临时 URL 会过期，因此不适合作为长期数据库字段。

建议调整为以下方案之一：

1. `notes` 只保存 `photo_id` 或稳定 `file_id`，备注列表查询时批量生成临时缩略图 URL。
2. `notes` 保存稳定云文件标识，API 返回前转换为临时 URL。
3. 如确需物化缩略图，应生成受控的缩略图文件，而不是保存临时 URL。

该数据模型应在 note 云函数开发前修正。

### 5.5 上传路径中的用户标识

架构设计：

```text
photos/{openid_short}/{timestamp}_{random8}.jpg
```

开发前需要定义：

- `openid_short` 的生成算法。
- 截断后是否可能碰撞。
- 是否会泄露可关联的用户标识。
- 小程序客户端如何安全获得该值。
- 同一用户在不同环境是否保持相同路径。

更稳妥的方案是：

- 使用不可逆、有盐的用户路径摘要；或
- 上传前由云函数签发不包含原始 OPENID 的路径前缀。

不建议直接截断并暴露 OPENID。

### 5.6 图片删除的跨资源一致性

架构当前描述为：

1. 删除云存储对象。
2. 在数据库事务中删除图片、备注和标签关系。

云存储与云数据库不能形成同一个 ACID 事务，因此必须明确补偿策略：

- 对象删除成功、数据库事务失败时如何处理。
- 数据库提交成功、对象删除失败时如何处理。
- 孤立对象和失效文件引用如何被 cleanup 发现。
- 删除请求如何保证幂等。
- 是否需要持久化删除阶段和最后一次错误。

推荐将删除建模为可恢复的状态机，而不是假设跨存储和数据库操作能够一次性原子完成。

### 5.7 注销和“解除微信绑定”

架构中的“解除微信绑定”需要明确技术含义。

普通云开发应用通常能够删除自身保存的用户记录、业务数据和文件，但不能撤销微信平台已经分配的 OPENID。

建议将注销完成定义为：

- 删除或匿名化业务用户记录。
- 删除图片、备注、标签和关联数据。
- 删除云存储对象。
- 后续相同 OPENID 再次进入时按新用户重新初始化。

同时应明确：

- 注销预计完成时间。
- 重试上限。
- 用户如何查询进度。
- 用户如何联系客服。
- 注销失败后的运营处理流程。

## 6. 发布前需要准备的账号和合规条件

以下事项可以不阻塞纯 UI 开发，但必须在提审前完成：

- 小程序主体认证。
- 开发者、体验者和管理员成员配置。
- 选择与图片笔记/效率工具业务匹配的服务类目。
- 完成小程序备案或确认现有备案状态。
- 配置小程序用户隐私保护指引。
- 准备用户协议和隐私政策。
- 说明图片、备注、标签和 EXIF 拍摄时间的处理目的。
- 说明数据存储位置、保存期限和删除方式。
- 说明账号注销方式和预计处理时限。
- 准备真实有效的客服联系方式。
- 准备提审体验账号和审核说明。
- 完成内容安全策略。
- 完成真机兼容性测试。

如果项目不需要昵称、头像、手机号等微信信息，不应为了“登录”额外请求这些权限。使用 `cloud.getWXContext().OPENID` 建立内部身份即可。

## 7. 当前项目配置问题

### 7.1 云开发环境为空

`miniprogram/app.js`：

```javascript
env: ""
```

在环境 ID 配置完成前，所有 `wx.cloud` 业务调用都无法正确定位资源。

### 7.2 公共和私有基础库版本不一致

`project.config.json`：

```json
"libVersion": "2.20.1"
```

`project.private.config.json`：

```json
"libVersion": "3.17.0"
```

私有配置会覆盖公共配置。不同开发人员如果没有相同私有配置，可能使用不同基础库进行构建和调试。

建议将团队统一使用的基础库版本写入公共配置，私有配置仅保留个人开发工具偏好。

### 7.3 路由仍为 QuickStart

当前 `miniprogram/app.json` 只有：

```text
pages/index/index
pages/example/index
```

与技术架构要求的业务路由不一致。

### 7.4 npm 工程尚未建立

当前不存在：

- `package.json`
- `package-lock.json`
- `miniprogram/package.json`
- `miniprogram_npm`
- `.gitignore`

这会导致：

- 无法锁定 TDesign 版本。
- 团队成员依赖安装结果不一致。
- npm 构建流程无法复现。
- 后续可能误提交 `node_modules` 或本地配置。

### 7.5 QuickStart 云函数权限不能沿用

现有 `quickstartFunctions`：

- 创建并操作 `sales` 集合。
- 调用 `wxacode.get`。
- 配置了小程序码 OpenAPI 权限。

这些能力不属于图片笔记核心业务。新云函数应按最小权限重新配置，不能复制 QuickStart 权限作为统一模板。

### 7.6 部署脚本仍指向示例函数

当前 `uploadCloudFunction.sh` 只部署：

```text
quickstartFunctions
```

需要改造为支持七个业务函数、目标环境和触发器部署的可重复流程。

### 7.7 缺少基础设施初始化与验收脚本

当前仓库没有：

- 集合创建脚本。
- 索引创建脚本或索引清单。
- 数据回填脚本。
- 环境健康检查脚本。
- 云函数批量部署配置。
- 数据库权限配置记录。

即使部分操作必须在控制台完成，也应在仓库中记录可审计的操作清单。

### 7.8 页面数量口径不一致

架构文档写“6 个页面”，但路由实际包括：

1. index
2. photos
3. notes
4. preview
5. settings
6. deletion-status
7. tag-manager

实际是七个路由页面。PG-003、PG-005、PG-010 为浮层组件，不是独立路由。开发排期和验收清单应统一为“七个路由页面 + 三个核心浮层 + 其他业务组件”。

## 9. 最小开工条件

如需尽快启动 S1 基础设施和 S2 上传核心，至少必须先满足：

1. AppID 归属及开发权限确认。
2. 创建 dev 云开发环境并提供 `envId`。
3. 确认云开发套餐、地域和付费主体。
4. 确认 Node.js 18 云函数运行时。
5. 锁定并验证 `wx-server-sdk` 版本。
6. 锁定 TDesign 版本并核对组件可用性。
7. 创建数据库集合和关键索引。
8. 验证服务端数据库事务。
9. 验证私有云存储上传、临时 URL 和缩略图处理。
10. 对内容安全方案形成明确决策。

其中，AppSecret 和腾讯云 SecretId/SecretKey 都不是当前小程序业务开发的必要输入，也不应向前端开发人员索取。

## 10. 建议的下一步

建议按以下顺序推进：

1. 由项目负责人确认 AppID、主体、管理员和开发成员。

5. 创建六个集合及索引，用最小云函数验证登录、事务、上传和临时 URL。
6. 验证通过后再进入正式页面及业务云函数开发。
