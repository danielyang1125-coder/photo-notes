## 1. 版本目标

### 1.1 变更背景

基线版本支持用户按上传时间浏览图片，并通过备注列表按备注创建时间或照片拍摄时间回看内容。随着用户持续上传书页、截图、旅行照片、设计参考、票据等不同主题的图片，仅依靠时间顺序难以完成跨时间、跨场景的主题化整理。

备注解决的是“这张图片记录了什么”，但无法表达“这张图片属于哪些主题”。本次增加轻量标签能力，使用户可以从一个或多个个人维度聚合图片，同时保持原有“打开即可查看图片”的低门槛体验。

### 1.2 核心目标

在不增加图片上传和日常浏览负担的前提下，使用户可以：

1. 为图片添加最多 5 个个人标签。
2. 从【全部】【未分类】或任一用户标签快速浏览对应图片。
3. 在图片详情中维护单张图片标签。
4. 在上传成功后，可选地为本批成功图片统一添加标签。
5. 通过简单的创建、重命名和删除完成标签维护。

### 1.3 设计原则

1. **图片优先**：进入【图片】页默认仍展示全部图片，不以标签列表替代图片流。
2. **标签可选**：不要求用户在上传前或上传过程中选择标签，未添加标签不影响任何核心能力。
3. **一次筛选**：V1.0.0 每次只按一个标签筛选，不提供多标签交集、并集或组合查询。
4. **轻量维护**：仅支持创建、重命名和删除，不提供颜色、图标、层级、拖动排序或标签合并。
5. **数据私有**：标签及图片关联仅本人可见，服务端必须校验用户和资源归属。
6. **失败可恢复**：标签操作失败不得错误修改页面结果，不得清空用户尚未提交的选择。
7. **低成本**：不建设标签推荐、标签搜索索引、AI 自动打标或管理后台。

### 1.4 建议验证指标

| 指标 | 建议目标 | 统计口径 |
|---|---:|---|
| 标签操作成功率 | ≥ 99% | 创建、重命名、删除、关联、移除成功请求数/有效请求数 |
| 标签筛选成功率 | ≥ 99% | 成功返回对应标签图片列表的次数/有效筛选请求次数 |
| 图片已分类率 | ≥ 60% | 已关联至少 1 个标签的有效图片数/使用过标签用户的有效图片总数 |
| 标签功能使用率 | ≥ 30% | 图片数达到 10 张且至少创建 1 个标签的用户数/图片数达到 10 张的用户数 |
| 标签反查完成率 | ≥ 95% | 点击用户标签后成功打开该标签下任一图片的会话数/有效标签筛选会话数 |

> 图片已分类率、标签功能使用率为 MVP 建议值。正式上线前需结合埋点方案确认分母、观察周期和去重口径。

### 1.5 本次增量包含

- 图片页默认展示全部图片，并根据用户标签数量自适应提供【新建标签】【管理】或【更多】入口。
- 按单个用户标签筛选图片。
- 用户标签创建、重命名和删除。
- 图片详情展示标签。
- 单张图片添加、移除标签。
- 上传结束后，为本批成功图片统一添加标签。
- 标签数量、名称、唯一性、排序和数据归属规则。
- 图片删除、标签删除、账号注销时的关联清理。
- 标签相关加载态、空态、错误态和异常恢复。
- 标签相关最低服务端数据契约和验收标准。

### 1.6 本次增量明确不包含

- 用标签列表替代【图片】页的默认图片流。
- 强制用户在上传前选择标签。
- 标签颜色、图标、封面和个性化样式。
- 父子标签、标签目录、相册层级和多级分类。
- 标签拖动排序、自定义排序和置顶。
- 多标签组合筛选。
- 标签搜索、图片全文搜索和搜索历史。
- 系统预置业务标签。
- AI、OCR 或规则自动生成标签。
- 标签推荐、相似标签和标签合并。
- 在图片瀑布流卡片上展示标签名称。
- 批量选择历史图片后统一修改标签。
- 标签共享、公开标签和多人协作。

## 3. 用户场景与业务流程

### 3.1 核心场景

#### 场景一：从标签回看主题图片

用户进入【图片】页，默认看到全部图片。用户点击“读书”标签后，页面只展示关联“读书”的图片；点击图片后仍按原流程进入图片详情。

#### 场景二：整理未分类图片

用户点击【未分类】，查看尚未添加任何标签的图片。用户进入某张图片详情，为其添加标签；返回后该图片从【未分类】结果中移除。

#### 场景三：为单张图片添加多个维度

用户在图片详情中为一张书页照片添加“读书”“产品设计”两个标签。该图片分别出现在这两个标签的筛选结果中。

#### 场景四：上传后批量归类

用户上传 8 张旅行照片，其中 7 张成功、1 张失败。上传结束后用户选择“旅行”标签，系统仅为 7 张成功图片添加标签；失败任务继续保留重试能力。

#### 场景五：维护标签

用户在标签管理页将“产品”重命名为“产品设计”；所有关联图片无需重新选择即可显示新名称。用户删除“临时”标签后，关联图片仍然保留。

### 3.2 BP-007 标签筛选与图片回看

**触发条件**：用户进入 PG-002 或点击某个筛选项。  
**参与角色**：个人用户。  
**前置条件**：账号状态为 `ACTIVE`。

**主流程**：

1. 用户进入 PG-002。
2. 系统默认选中【全部】，加载全部图片首屏。
3. 系统加载本人标签，并根据标签总数展示对应的快捷标签和管理入口。
4. 用户点击【未分类】或某个用户标签。
5. 系统重置图片分页并按当前筛选条件加载首屏。
6. 用户点击图片进入 PG-004。
7. 用户返回 PG-002 时，当前会话保留筛选条件、已加载列表和滚动位置。

**分支流程**：

- 用户点击【全部】：加载本人全部有效图片。
- 用户点击【未分类】：仅加载没有任何有效标签关联的图片。
- 用户没有自定义标签时：显示【＋新建标签】；创建成功后新标签自动成为当前筛选项。
- 用户有 1～5 个自定义标签时：展示全部自定义标签和【管理】；点击【管理】进入 PG-009。
- 用户有 6～100 个自定义标签时：展示最近使用的 5 个标签和【更多】；点击【更多】进入 PG-009。
- 用户从 PG-009 点击某个标签后：返回 PG-002 并以该标签筛选。
- 小程序冷启动或新会话首次进入 PG-002：始终恢复为【全部】。

**异常流程**：

- 标签列表加载失败：全部图片仍可浏览；标签区显示轻量错误和重试入口。
- 图片筛选失败：保留当前已选筛选项，列表显示错误态和重试。
- 当前标签已在其他设备删除：提示“标签已不存在”，刷新标签区并切换到【全部】。
- 筛选结果为空：显示对应空态，不自动切换筛选项。

**后置条件**：用户看到的图片均属于本人，并符合当前唯一筛选条件。

### 3.3 BP-008 单张图片标签维护

**触发条件**：用户在 PG-004 点击标签区域的“添加”或“编辑”。  
**参与角色**：个人用户。  
**前置条件**：图片存在且属于当前用户，账号状态为 `ACTIVE`。

**主流程**：

1. 系统打开 PG-010。
2. 系统加载当前图片已关联标签和本人标签列表。
3. 用户勾选或取消勾选标签，最多选中 5 个。
4. 用户可在 PG-010 内创建新标签；创建成功后新标签自动选中。
5. 用户点击“保存”。
6. 服务端按增量方式添加、移除关联关系。
7. 保存成功后关闭 PG-010，刷新 PG-004 标签区。
8. 其他页面在下次显示或刷新时同步最新标签和筛选结果。

**异常流程**：

- 图片已在其他设备删除：禁止保存，提示“图片已被删除或不存在”，关闭编辑层并返回图片列表。
- 已选标签在其他设备被删除：保留其他选择，刷新标签列表并提示“部分标签已不存在，请重新确认”。
- 保存时网络或服务异常：保持 PG-010 打开并保留未提交选择，允许重试。
- 重复点击保存：保存期间按钮禁用，不得创建重复关联。
- 用户取消或关闭：不修改图片标签；本次未保存选择不跨页面和跨会话保留。

**后置条件**：图片拥有 0～5 个有效标签；图片与标签关系不重复。

### 3.4 BP-009 标签创建、重命名与删除

**触发条件**：用户从 PG-009 或 PG-010 发起标签维护。  
**参与角色**：个人用户。  
**前置条件**：账号状态为 `ACTIVE`。

#### 创建标签主流程

1. 用户点击“新建标签”。
2. 系统显示标签名称输入框。
3. 用户输入名称并提交。
4. 前后端按 BR-032～BR-035 校验。
5. 创建成功后刷新标签列表。
6. 若从 PG-010 创建，新标签自动选中。

#### 重命名标签主流程

1. 用户在 PG-009 对某个标签点击“重命名”。
2. 系统显示原名称并允许编辑。
3. 用户提交新名称。
4. 服务端校验并更新标签。
5. 所有引用该标签的位置显示新名称，图片关联关系保持不变。

#### 删除标签主流程

1. 用户在 PG-009 对某个标签点击“删除”。
2. 系统展示标签名称、关联图片数量和“不删除图片”的说明。
3. 用户确认。
4. 服务端删除标签及全部图片标签关联。
5. 原本仅关联该标签的图片进入【未分类】。
6. 页面刷新标签列表和相关图片数量。

**异常流程**：

- 名称为空、超长、包含换行或控制字符：禁止提交并显示对应提示。
- 名称与本人已有标签重复：禁止创建或重命名，提示使用已有标签。
- 标签总数达到 100：禁止创建，提示先删除不需要的标签。
- 标签已被其他设备删除：按操作成功处理并刷新标签列表。
- 删除或重命名失败：页面数据不提前变化，保留输入并允许重试。

### 3.5 BP-010 上传成功图片批量添加标签

**触发条件**：PG-003 中当前批次所有任务均已结束，且至少 1 张图片上传成功。  
**参与角色**：个人用户。  
**前置条件**：账号状态为 `ACTIVE`。

**主流程**：

1. 上传面板展示成功数和失败数。
2. 系统提供“为本批图片添加标签”和“完成”。
3. 用户点击“为本批图片添加标签”，打开 PG-010。
4. 用户选择 1～5 个标签，或创建新标签。
5. 用户点击“保存”。
6. 服务端为本批全部成功图片添加所选标签。
7. 成功后返回 PG-003，显示“已为 N 张图片添加标签”。
8. 用户点击“完成”关闭上传面板并刷新 PG-002。

**分支流程**：

- 用户点击“完成”：跳过添加标签，不影响成功图片。
- 批次部分失败：仅成功入库的图片参与批量关联。
- 失败任务后续重试成功：视为新的成功结果，不自动继承此前已完成的批量标签操作；用户可在图片详情中补充标签。

**异常流程**：

- 批量关联失败：PG-010 保持打开并保留选择，允许重试或取消。
- 请求重复提交或成功回调重复：同一图片与标签仅保留一条有效关联。
- 部分图片已被其他设备删除：服务端不得为不存在图片创建关联；若其他有效图片已完成关联，返回明确的成功数和失效数。

**后置条件**：成功处理的图片均关联相同标签；上传失败或取消任务没有图片标签关联。

## 4. 数据实体定义

### 4.1 标签 Tag

| 属性 | 必填 | 说明 |
|---|---:|---|
| 标签 ID | 是 | 服务端唯一标识 |
| 用户 ID | 是 | 标签所有者，用于数据隔离 |
| 标签名称 | 是 | 用户看到的原始展示名称 |
| 规范化名称 | 是 | 用于本人范围内唯一性校验，不直接展示 |
| 关联图片数量 | 是 | 当前有效关联图片数，非负整数 |
| 最近使用时间 | 是 | 最近一次成功筛选或成功关联图片的服务端时间 |
| 创建时间 | 是 | 服务端创建时间 |
| 更新时间 | 是 | 最近一次重命名或业务更新的服务端时间 |

### 4.2 图片标签关联 PhotoTag

| 属性 | 必填 | 说明 |
|---|---:|---|
| 关联 ID | 是 | 服务端唯一标识，或由图片 ID 与标签 ID 形成唯一关系 |
| 用户 ID | 是 | 关联关系所有者，必须与图片、标签所有者一致 |
| 图片 ID | 是 | 关联的有效图片 |
| 标签 ID | 是 | 关联的有效标签 |
| 创建时间 | 是 | 关联成功的服务端时间 |

### 4.3 实体关系

- 用户 `1:N` 标签。
- 图片 `N:M` 标签，通过图片标签关联表达。
- 一个用户标签可以关联 `0:N` 张本人图片。
- 一张图片可以关联 `0:5` 个本人标签。
- 图片、标签和图片标签关联的用户 ID 必须一致。
- 【全部】和【未分类】为查询口径，不创建标签实体。

### 4.4 数据权限

| 对象 | 查看 | 创建 | 修改 | 删除 |
|---|---|---|---|---|
| 本人标签 | 是 | 是 | 是 | 是 |
| 本人图片标签关联 | 是 | 是 | 是 | 是 |
| 他人标签或关联 | 否 | 否 | 否 | 否 |
| 【全部】/【未分类】虚拟集合 | 是 | 不适用 | 不适用 | 不适用 |

服务端必须基于当前登录用户校验标签、图片及关联关系，禁止信任客户端传入的用户 ID，禁止通过标签 ID 推断或返回其他用户数据。

### 4.5 生命周期与级联规则

| 触发动作 | 标签 | 图片 | 图片标签关联 |
|---|---|---|---|
| 创建标签 | 新增 | 不变 | 不变 |
| 重命名标签 | 名称更新 | 不变 | 不变 |
| 删除标签 | 删除 | 不删除 | 删除该标签的全部关联 |
| 删除图片 | 不删除 | 删除 | 删除该图片的全部关联 |
| 注销账号 | 全部删除 | 按 F-015 删除 | 全部删除 |

标签和图片标签关联不设计独立业务状态机；有效性由实体是否存在及归属关系决定。

## 6. 功能详细描述

### 6.1 F-016 标签浏览与图片筛选

- **用户故事**：作为个人用户，我想按主题标签聚合查看图片，以便快速回顾同一主题下跨时间保存的内容。
- **关联角色**：个人用户。
- **所属端**：用户端小程序。
- **前置条件**：用户身份有效。
- **操作权限**：仅可查看本人标签和本人图片。
- **入口**：PG-002 顶部标签筛选区。
- **主流程**：进入图片页 → 默认【全部】→ 点击【未分类】或用户标签 → 重置分页 → 加载对应图片 → 点击图片查看详情。
- **业务规则**：BR-029、BR-030、BR-039～BR-043、BR-052～BR-054。

**交互说明**：

- 触发方式：点击筛选项后立即请求，不需要额外点击查询。
- 加载态：筛选区保持可见，图片列表区域显示骨架块。
- 成功反馈：不显示额外 Toast，选中态和图片结果直接反馈。
- 失败反馈：保留筛选选中态，列表显示“图片加载失败，点击重试”。
- 空态：
  - 【全部】为空：沿用“还没有图片”及上传入口。
  - 【未分类】为空：显示“所有图片都已添加标签”。
  - 用户标签为空：显示“这个标签下还没有图片”，提供“查看全部图片”。
- 确认机制：不适用。
- 实时校验：点击已删除或无权访问的标签时，服务端拒绝并回到【全部】。

**输入分解**：

| 输入变量 | 等价类 | 引用规则 |
|---|---|---|
| 筛选范围 | 全部、未分类、有效用户标签、失效标签、他人标签 | BR-029/BR-030/BR-042 |
| 标签数量 | 0、1～5、6～100 | BR-041 |
| 筛选结果 | 有图片、无图片、请求失败 | BR-051/BR-052 |
| 页面进入方式 | 新会话、同会话返回 | BR-053 |

**异常流程**：

- 他人标签 ID：服务端拒绝，不返回任何图片或标签信息。
- 标签已删除：提示“标签已不存在”，刷新标签区并切换到【全部】。
- 请求失败：列表错误态，点击重试仍使用当前筛选条件。
- 分页期间标签被删除：停止后续分页，提示并切换到【全部】。

### 6.2 F-017 标签创建、重命名与删除

- **用户故事**：作为个人用户，我想维护自己的主题标签，以便标签名称始终符合我的整理方式。
- **关联角色**：个人用户。
- **所属端**：用户端小程序。
- **前置条件**：用户身份有效。
- **操作权限**：仅可维护本人标签。
- **入口**：PG-009、PG-010。
- **业务规则**：BR-029、BR-032～BR-040、BR-044～BR-048、BR-051、BR-052、BR-054。

**交互说明**：

- 创建：点击“新建标签”打开输入层；提交期间按钮禁用。
- 创建成功：Toast“标签已创建”；PG-010 中自动选中，PG-009 中刷新列表。
- 重命名：操作菜单选择“重命名”，输入框预填原名称。
- 重命名成功：Toast“标签已更新”，列表和引用位置显示新名称。
- 删除：必须二次确认，文案明确标签关联图片数且不删除图片。
- 删除成功：Toast“标签已删除”，刷新标签和图片数量。
- 失败反馈：输入层保持打开并保留内容；删除失败不提前移除列表项。
- 空态：PG-009 无用户标签时显示“还没有标签”及“新建标签”。
- 实时校验：显示 Unicode code point 计数 `N/12`；输入超过 12 时阻止继续输入。

**输入分解**：

| 输入变量 | 等价类 | 引用规则 |
|---|---|---|
| 标签名称长度 | 0、1、12、13 个 code point | BR-032 |
| 字符类型 | 普通字符、内部空格、Emoji、换行、控制字符 | BR-032/BR-033 |
| 唯一性 | 新名称、同名、仅拉丁大小写不同、本人外同名 | BR-034 |
| 名称类型 | 普通名称、全部、未分类 | BR-035 |
| 用户标签总数 | 0～99、100 | BR-036 |
| 标签状态 | 有效、已被删除 | BR-044/BR-045 |
| 关联图片数 | 0、1、多张 | BR-045/BR-046/BR-054 |

**删除确认文案**：

`确定删除标签“{标签名称}”吗？该标签与 N 张图片的关联将被移除，但不会删除图片或备注。`

**异常流程**：

- 空名称：提示“请输入标签名称”。
- 超长：提示“标签名称最多 12 个字符”。
- 非法字符：提示“标签名称不能包含换行或控制字符”。
- 重名：提示“标签已存在，请直接使用已有标签”。
- 保留名称：提示“该名称为系统保留名称，请更换”。
- 标签数达到 100：提示“最多创建 100 个标签，请先删除不需要的标签”。
- 删除已不存在标签：按成功处理并刷新。
- 网络异常：保留输入或原列表状态，允许重试。

### 6.3 F-018 单张图片标签维护

- **用户故事**：作为个人用户，我想为一张图片添加或移除多个标签，以便从不同主题维度找到它。
- **关联角色**：个人用户。
- **所属端**：用户端小程序。
- **前置条件**：图片存在且属于当前用户。
- **操作权限**：仅可维护本人图片与本人标签的关联。
- **入口**：PG-004 标签区“添加”或“编辑”。
- **业务规则**：BR-029～BR-038、BR-044、BR-048、BR-051～BR-054。

**交互说明**：

- 当前图片无标签时显示“还没有标签”及“添加标签”。
- 当前图片有标签时完整展示，点击“编辑”打开 PG-010。
- PG-010 按最近使用顺序展示本人标签，并标记当前已选项。
- 保存提交选中集合相对初始集合的新增和移除项。
- 保存期间按钮禁用并显示加载状态。
- 保存成功：关闭 PG-010，Toast“标签已更新”。
- 保存失败：PG-010 保持打开，选择不丢失。
- 取消：有改动时提示“放弃本次标签修改？”；无改动直接关闭。
- 图片瀑布流卡片不显示标签名称。

**输入分解**：

| 输入变量 | 等价类 | 引用规则 |
|---|---|---|
| 初始标签数 | 0、1～4、5 | BR-031 |
| 保存标签数 | 0、1～4、5、超过 5 | BR-031/BR-038 |
| 标签归属 | 本人标签、他人标签 | BR-029 |
| 标签有效性 | 有效、保存前被删除 | BR-051/BR-052 |
| 图片有效性 | 有效、保存前被删除 | BR-029/BR-051 |
| 请求次数 | 单次、重复提交 | BR-048 |

**异常流程**：

- 尝试选择第 6 个：不改变选择，提示“一张图片最多添加 5 个标签”。
- 他人标签：服务端拒绝，图片关系不变。
- 部分标签失效：刷新可选标签，保留其他选择并要求用户重新确认。
- 图片已删除：禁止保存，提示后返回图片列表。
- 保存失败：保留选择，用户可重试或取消。

### 6.4 F-019 上传成功图片批量添加标签

- **用户故事**：作为个人用户，我想在一批图片上传成功后统一添加标签，以便用一次操作完成同主题图片归类。
- **关联角色**：个人用户。
- **所属端**：用户端小程序。
- **前置条件**：当前上传批次至少有 1 张成功图片，所有任务均已结束。
- **操作权限**：仅可操作本人当前批次成功图片和本人标签。
- **入口**：PG-003 上传结果区“为本批图片添加标签”。
- **业务规则**：BR-029、BR-031～BR-040、BR-048～BR-051、BR-054。

**交互说明**：

- 标签操作为可选步骤，“完成”始终可用，不强制添加标签。
- 打开 PG-010 时默认不选标签。
- 用户选择 1～5 个标签后保存。
- 保存成功后显示“已为 N 张图片添加标签”。
- 已完成批量添加后再次进入，可重复选择；服务端按集合合并和幂等规则处理。
- 上传失败或取消任务不进入 `photoIds`。
- 批量添加失败不改变上传任务成功状态，不影响用户关闭上传面板。

**输入分解**：

| 输入变量 | 等价类 | 引用规则 |
|---|---|---|
| 成功图片数 | 0、1、2～20 | BR-049 |
| 失败/取消任务数 | 0、1、多张 | BR-049 |
| 选择标签数 | 0、1～4、5、超过 5 | BR-031/BR-038 |
| 图片有效性 | 全部有效、部分被删除 | BR-049/BR-051 |
| 请求 | 首次、重复请求 | BR-048/BR-050 |

**异常流程**：

- 成功图片数为 0：不展示批量标签入口。
- 未选择标签：保存按钮禁用；用户可以取消或直接完成上传流程。
- 批量操作部分图片失效：有效图片正常处理，返回成功数和失效数。
- 网络或服务异常：保留标签选择，允许重试；成功图片仍保持已上传状态。

| 管理 | 自适应操作入口 | 用户标签为 1～5 个时展示，进入 PG-009 |
| 更多 | 自适应操作入口 | 用户标签为 6～100 个时展示，进入 PG-009 |

- 筛选区为单行横向布局，用户标签名称超出单项最大展示宽度时单行省略。
- 【全部】【未分类】始终位于筛选区前部；【＋新建标签】【管理】【更多】应与用户标签的选中样式保持区分。
- 同时只有一个筛选项处于选中态。
- 用户点击【＋新建标签】后复用 PG-010 的标签创建能力；创建成功后关闭创建层，在 PG-002 插入新标签、自动选中并展示该标签的空结果。

## 8. 最低服务端数据契约

> 本节定义产品所需的最低输入、输出和行为，不限定云函数名称、数据库字段类型或技术实现。

### 8.1 标签列表

**输入**：

- 分页或全量查询参数。
- 排序固定为最近使用时间降序。

**输出**：

- 标签 ID。
- 展示名称。
- 关联图片数量。
- 最近使用时间。
- 创建时间、更新时间。

**行为**：

- 仅返回当前用户标签。
- PG-002 可获取最近使用前 5 个；PG-009/PG-010 获取完整列表。

### 8.2 创建标签

**输入**：标签名称。  
**输出**：新标签摘要。  
**行为**：

- 服务端重复执行 BR-032～BR-036 校验。
- 创建和唯一性校验应避免并发生成规范化同名标签。

### 8.3 重命名标签

**输入**：标签 ID、新名称。  
**输出**：更新后的标签摘要。  
**行为**：

- 校验当前用户归属和名称唯一性。
- 关联关系不变。

### 8.4 删除标签

**输入**：标签 ID。  
**输出**：删除结果、移除关联数量。  
**行为**：

- 删除标签及全部关联，不删除图片和备注。
- 重复删除按成功处理。

### 8.5 获取及修改单图标签

**获取输入**：图片 ID。  
**获取输出**：当前图片标签摘要列表。  
**修改输入**：图片 ID、待新增标签 ID、待移除标签 ID、幂等请求标识。  
**修改输出**：图片最新标签摘要列表。

**行为**：

- 使用增量变更，避免并发操作静默覆盖其他未涉及标签。
- 操作前校验图片、标签均属于当前用户。
- 合并后标签数不得超过 5。
- 重复请求不得重复创建或重复计数。

### 8.6 批量添加标签

**输入**：

- 当前上传批次成功图片 ID 列表。
- 标签 ID 列表。
- 批次或请求幂等标识。

**输出**：

- 成功图片数。
- 失效图片数。
- 已关联标签摘要。

**行为**：

- 图片数最多 20，标签数为 1～5。
- 仅处理当前用户有效图片和标签。
- 每张图片使用集合合并语义。
- 单个失效图片不应回滚其他有效图片的成功关联，但必须返回明确结果。

### 8.7 图片列表

**新增查询范围**：

- `ALL`：本人全部有效图片。
- `UNCATEGORIZED`：本人没有任何有效标签关联的图片。
- `TAG`：本人关联指定标签的图片，同时传入标签 ID。

**输出保持**：

- 图片卡片字段保持基线约定，不增加标签名称。

**行为**：

- 延续每页 20 张和上传时间降序。
- `TAG` 范围须校验标签归属；标签不存在或不属于本人时不得返回图片。

### 8.8 图片详情

**新增输出**：当前图片全部标签摘要，最多 5 个。  
**行为**：图片和标签必须属于同一当前用户。

### 8.9 删除和注销

- 删除图片：同步移除图片标签关联，并更新相关标签图片数量。
- 删除标签：同步移除标签关联，不删除图片。
- 注销账号：清理全部用户标签和图片标签关联；任一阶段失败时继续保持 `DELETING` 并自动重试。

### 8.10 通用错误类型

| 错误类型 | 说明 | 前端处理 |
|---|---|---|
| `TAG_NOT_FOUND` | 标签不存在或已删除 | 刷新标签列表并提示失效 |
| `TAG_ACCESS_DENIED` | 标签不属于当前用户 | 拒绝操作，不展示资源信息 |
| `TAG_NAME_INVALID` | 名称长度或字符不合法 | 保留输入并展示字段错误 |
| `TAG_NAME_DUPLICATED` | 规范化名称重复 | 提示使用已有标签 |
| `TAG_LIMIT_REACHED` | 用户标签达到 100 | 禁止创建 |
| `PHOTO_TAG_LIMIT_REACHED` | 单图合并后超过 5 | 保留选择并提示上限 |
| `PHOTO_NOT_FOUND` | 图片不存在或已删除 | 关闭关联操作并刷新图片数据 |
| `USER_NOT_ACTIVE` | 用户非 ACTIVE | 按账号状态进入对应受限流程 |

## 9. 非功能需求

### 9.1 性能

| 指标 | 要求 |
|---|---|
| 快捷标签首屏 | PG-002 最近使用 5 个标签 P95 ≤ 800 ms，可与图片首屏并行加载 |
| 全部标签列表 | 100 个标签以内 P95 ≤ 1 秒 |
| 标签筛选图片首屏 | 20 张图片 P95 ≤ 2 秒，不含缩略图下载 |
| 单图标签保存 | P95 ≤ 1 秒 |
| 批量标签保存 | 20 张图片、5 个标签时 P95 ≤ 2 秒 |

标签能力不得使基线 PRD 图片列表首屏 P95 ≤ 3 秒的总体要求失效；标签接口失败时全部图片仍须可浏览。

### 9.2 一致性

- 标签规范化名称在当前用户范围内唯一。
- 图片与标签关联不得重复。
- 单图有效标签数不得超过 5。
- 标签图片数量不得为负，并应与有效关联一致。
- 删除图片、删除标签、账号注销必须清理对应关联。
- 页面仅在服务端确认后展示操作成功。
- 关联计数异常时应具备后台校正能力，不建设用户可见管理后台。

### 9.3 安全与隐私

- 标签名称属于用户内容，默认仅本人可见。
- 服务端验证标签、图片及关联的所有权。
- 日志和埋点不得记录标签名称、图片内容、备注内容或可直接访问的私有 URL。
- 错误信息不得泄露他人标签是否存在、名称或关联数量。
- 账号注销的数据清理范围必须包含标签及关联。

### 9.4 可用性

- 标签功能不可阻断图片上传、全部图片浏览、备注维护和删除等基线能力。
- 标签列表失败时 PG-002 仍允许浏览全部图片。
- 标签操作失败时保留用户未提交选择。
- 所有标签点击区域不小于 44 × 44 px，选中态不能仅依赖颜色。

### 9.5 成本约束

- 不新增独立搜索服务或标签搜索索引。
- 不保存标签颜色、图标、封面和层级数据。
- 不建设系统标签配置后台。
- 不调用 AI、OCR 或第三方分类服务。
- 标签关联查询应通过合理的数据结构和索引满足分页性能，不允许前端下载全部图片后本地筛选。

### 9.6 可观测性

至少记录以下不含用户内容的事件：

- 标签创建、重命名、删除成功或失败及错误类型。
- 单图标签添加、移除成功或失败，记录标签数量但不记录名称。
- 上传后批量添加标签的入口曝光、使用、跳过、成功和失败。
- 【全部】【未分类】和用户标签筛选类型及结果数量区间，不记录标签 ID 的可逆用户内容映射。
- 标签筛选后打开图片是否成功。
- 标签数量上限和单图标签上限触发次数。
- 删除图片、删除标签和注销时关联清理成功或失败。

### 10.2 输入组合策略

- F-016～F-019 均为 P1，采用 Pairwise 组合策略。
- AC-044～AC-075 覆盖主要等价类、关键边界、权限、幂等、删除和异常恢复。
- 标签无独立状态机，不增加状态转移矩阵验收；实体存在性、数据归属和级联规则通过正反向场景验收。

### 10.3 非功能验收

| 验收项 | 标准 | 方法 |
|---|---|---|
| 快捷标签性能 | 最近使用前 5 个 P95 ≤ 800 ms | 预置标签后接口测试 |
| 标签筛选性能 | 20 张图片 P95 ≤ 2 秒 | 不同标签数量下接口测试 |
| 单图保存性能 | P95 ≤ 1 秒 | 单图 0～5 标签压力测试 |
| 批量保存性能 | 20 张图片 × 5 标签 P95 ≤ 2 秒 | 批量关联测试 |
| 数据隔离 | 任意用户无法访问他人标签和关联 | 越权接口测试 |
| 名称唯一性 | 并发创建规范化同名标签只能成功一个 | 并发测试 |
| 关联幂等 | 重复请求不生成重复关系或计数 | 重放请求和数据核对 |
| 删除一致性 | 删除标签不删除图片；删除图片清理关联 | 数据库和页面联合核对 |
| 注销一致性 | 标签及关联纳入注销清理和失败重试 | 接口、数据库及真机核对 |
| 隐私 | 日志和埋点不包含标签名称或用户内容 | 日志抽查和埋点检查 |
| 可用性 | 标签接口失败不阻断全部图片浏览 | 故障注入测试 |

## 12. 风险、假设与待确认项

### 12.1 主要风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 用户不主动整理 | 【未分类】持续堆积，标签价值低 | 标签非强制；提供上传后批量入口，观察分类率 |
| 标签数量过多 | 快捷筛选和选择效率下降 | 最多 100 个，快捷区仅展示最近 5 个 |
| 标签同义或近义重复 | 分类分散 | 规范化同名拦截；V1.0.0 不增加智能合并 |
| 标签筛选拖慢图片页 | 破坏核心浏览体验 | 默认全部图片并行加载；标签失败不阻断图片 |
| 删除级联不完整 | 计数错误、未分类口径错误 | 服务端级联、幂等、计数校正及一致性验收 |
| 多设备并发维护 | 标签被删除或关系冲突 | 增量关联、失效刷新、服务端权威数据 |

| 默认图片筛选 | 全部 |

| 标签排序 | 最近使用时间降序 |
| 标签是否必填 | 否 |

## 13. 术语

| 术语 | 定义 |
|---|---|
| 标签 | 用户创建并用于聚合本人图片的轻量主题标识 |
| 用户标签 | 有真实标签实体、可创建、重命名和删除的本人标签 |
| 全部 | 本人全部有效图片的系统虚拟查询范围 |
| 未分类 | 没有任何有效标签关联的本人图片虚拟查询范围 |
| 图片标签关联 | 图片和用户标签之间的多对多关系 |
| 最近使用时间 | 标签最近一次成功用于筛选或成功关联图片的服务端时间 |
| 规范化名称 | 标签名称完成去除首尾空白、Unicode NFC 和拉丁字母大小写归一后的唯一性比较值 |
| 批量添加标签 | 为当前上传批次中已成功入库的图片统一增加相同标签 |
